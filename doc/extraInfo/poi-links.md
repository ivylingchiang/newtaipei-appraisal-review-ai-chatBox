#### 為什麼查不到地塊大小——不是代碼查錯

實測 `F170110`（新北市樹林區樟樹窟段，樹林區真實段代碼）與 `F150045`（三峽區礁溪段），
**兩者回傳完全相同的 68 個欄位結構**，其中：

- **沒有任何面積欄位**（全文無「面積」字樣）
- 唯一的幾何相關欄位是 `WestBoundLongitude`／`EastBoundLongitude`／
  `SouthBoundLatitude`／`NorthBoundLatitude`，**實測四欄全為 `0`**
- `GeometricObjectType` = `surface`、`SpatialRepresentationType` = `vector`
  ——這是在描述「地籍圖是向量面圖徵」這個*資料型態*，不是給你圖形

換句話說，這是一支 **ISO 19115 式的圖資編目服務（metadata catalog）**，
回答的是「這張地籍圖是誰測的、比例尺多少、找誰買」，
而不是「這塊地多大、在哪裡」。**換任何代碼都一樣。**

該服務自己的欄位就寫明了真正的取得方式：

- `AccessRestriction` = `restricted`、`GetRestriction` = `restricted`
- `Subscription` = 「使用者可至本地政事務所臨櫃申購或是採線上方式申購地籍圖圖檔」

**地籍圖形與宗地面積屬申購制，不在任何免費開放 API 上。**

#### 唯一可用之處：段名↔段代碼對照

`LotCode` 組成為 **7 碼＝縣市(1)＋鄉鎮市區(2)＋段小段(4)**，新北市縣市碼為 `F`。

```
# 縣市
GET https://lisp.land.moi.gov.tw/MMS/Handle/QueryHandler.ashx?type=county
# 地政事務所（新北市 9 所：FA板橋 FB新莊 FC新店 FD汐止 FE淡水 FF瑞芳 FG三重 FH中和 FI樹林）
GET .../QueryHandler.ashx?type=office&CountyCode=F
# 鄉鎮市區（樹林區=FI/17，金山區=FD/25）
GET .../QueryHandler.ashx?type=town&CountyCode=F&OfficeCode=FI
# 段清單（樹林所 202 筆；限樹林區 TownCode=17 為 70 筆）
GET .../QueryHandler.ashx?type=query&CountyCode=F&OfficeCode=FI&TownCode=17&LotCode=&Keyword=&CurrentPage=1
# 單段詮釋資料
POST .../MapMetadataService.asmx/RequestService   body: LotCode=F170110
```

同樣的對照表在**國土測繪中心 API 也拿得到，且為 UTF-8、免跳頁**，建議優先用：

```
GET https://api.nlsc.gov.tw/other/ListTown/F            # F17 樹林區、F25 金山區
GET https://api.nlsc.gov.tw/other/ListLandSection/F/F17 # office=FI, sectcode=0106 …
```

兩者段代碼一致（NLSC `sectcode=0106` ＝ LISP `LotCode=F170106`），可互相驗證。

**結論：不解決「沒有任何一個來源提供地價區段界線」的缺口。**

#### 檔案格式（踩過的坑）

- `.grd`：純文字，每行 `X Y H`（TWD97 TM2 公尺、高程基準 TWVD2001），可直接讀
- `.hdr`：**Big5、無欄位名的位置式格式**（非 ESRI ASCII Grid，GDAL 不可直讀）。
  行序（0-based）：
  `[1]圖號 [3]TWD97[2010] [4]TWVD2001 [5]比例尺 [6][7]網格間距 [8]點數 [9]ncols [10]nrows [11]X原點 [12]Y原點`

> ⚠️ **`[12]` 的 Y 原點是圖幅「下緣」（最小 Y），不是上緣。**

#### 能填哪些表3 欄位

坡度以 3×3 鄰域 Horn 法計算，於區段中心點半徑 100 m 內取樣平均。

| 表3 欄位 | 最大修正率 | 判準 | DTM 能做到什麼 |
| --- | --- | --- | --- |
| **傾斜度 `slope`** | ±15 % | 「平均坡度未滿5度／5~10／10~15／15~20／20度以上」 | ✅ **完全可自動判級**。判準是純角度門檻，DTM 直接算得出，無須人工詮釋 |
| 地勢 `terrain` | ±10 % | 「極平坦堅硬／平坦地／緩傾斜地／低地、溼地／地勢孤劣地」 | ⚠️ **部分**。平坦↔緩傾斜可由坡度區分；「低地」可由相對高程（區段高程 vs 周邊）判斷；但「堅硬」屬地質、「溼地」屬地被，**DTM 無法認定** |
| 排水之良否 `drainage` | ±10 % | 「極完善～極不良」 | ⚠️ **僅反證**。可偵測窪地／局部低點（潛在積水），但判準問的是排水**設施**完善度，屬人工構造物，DTM 不能判「完善」 |
| 日照 `sunlight` | ±10 % | 「充分～大部分陰雨」 | ⚠️ **弱**。可算坡向(aspect)與地形遮蔽；但判準講的是氣候與建物遮蔽，DTM 只能排除「被山體擋住」這種極端情形 |
| 景觀 `view` | ±5 % | 「視野極寬廣～極差」 | ⚠️ **弱**。可做視域分析(viewshed)量化「視野寬廣」，但「景觀優美」為主觀判斷，不可自動判級 |

**❌ 不能做**：表5 宗地個別因素的 `area` 面積／`width` 寬度／`depth` 深度／`shape` 形狀。
這四項需要**地籍圖形**，DTM 只有高程，沒有地籍界線（見第 19 筆）。
