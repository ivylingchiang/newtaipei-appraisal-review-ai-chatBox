**三個必須先講的結論：**

1. **`新北市重要地標資訊` 是這批資料裡唯一的主力。** 2,056 筆、29 種地標類型、TWD97 座標零缺漏、每日更新，
   一支 API 就同時覆蓋表3 的**大型車站（火車站／捷運站）、學校（國小／國中／完中／高中職／大專）、
   服務性設施（醫院／衛生所／機關）** 三大類。樹林區 95 筆。
2. **沒有任何一個來源提供「地價區段界線」。** 表3 的距離一律自**本區段中心點**起算（[dev/03 §S2](03-設施類區域因素填表規範.md)），
   而區段幾何不在這 18 個來源裡，也不在新北開放平台上（§6.1）。**這是全案最大的缺口**：
   在取得區段圖前，本批資料只能做「**比對現有表3 填載是否合理**」，不能做「**從零產生表3**」。
3. **嫌惡設施（特殊設施＋環境污染）的覆蓋率最差，而它們的修正率最高。** 樹林住宅用地環境污染單項 ±20 %、
   廢棄物處理 ±15 %（[dev/03 §3.2](03-設施類區域因素填表規範.md)），但瓦斯槽、儲油槽、高壓鐵塔、
   污水處理場、垃圾掩埋場、噪音污染**完全無來源**（§5）。

## 1. 評分定義

### 1.1 「API 正確」四個等級

| 等級            | 意義                                                                          |
| --------------- | ----------------------------------------------------------------------------- |
| ✅ 正確         | 端點可直接呼叫、回傳結構化資料、欄位與說明相符、可分頁取得全量                |
| ⚠️ 可用但有坑 | 可取得資料，但有編碼／分隔符／分頁上限／欄位語意等需處理的問題                |
| 🔶 需轉址       | `data.gov.tw` 的 dataset 頁面本身不是 API，須先查 metadata 取得實際檔案 URL |
| ❌ 失效         | 無法取得                                                                      |

> **poi-links.md 的連結全部是 dataset 網頁，不是 API。** 本文為每一筆補上**實際可呼叫的端點**（§3~§5 的「端點」欄）。
> 另：原連結都帶 `?fbclid=...` 追蹤參數，呼叫時**必須去除**，否則 `data.gov.tw` 的 REST API 會回 404。

### 1.2 「信任程度」四個等級

| 等級               | 判準                                                   | 用途                                                                   |
| ------------------ | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| **A 高**     | 主管機關原始名冊＋自帶座標＋更新頻率 ≥ 每日＋涵蓋完整 | 可作為**判級輸入**與**退補依據**                           |
| **B 中**     | 主管機關原始名冊，但缺座標或更新頻率低（年更）         | 可作為**交叉核對**與**候選清單**，距離需人工或地理編碼確認 |
| **C 低**     | 涵蓋明顯不完整，或語意與表3 欄位定義不完全吻合         | 僅供**提示查估人員**，不得據以判定「無」                         |
| **D 不建議** | 語意不符、或粒度不足以算距離                           | 不進入判級流程；僅作背景參考                                           |

> ⚠️ **C／D 級的共同紅線：不得用來判定「無此設施」。**
> 依 [dev/03 §3.4(c)](03-設施類區域因素填表規範.md)，正向設施填「無」＝最劣級、嫌惡設施填「無」＝最優級，
> 兩者都會**直接改變修正率**。以涵蓋不全的資料推定「無」，等同偽造勘查結果。
> C／D 級資料只能支撐「**找到了**，請查估人員確認」，不能支撐「**找不到，所以沒有**」。

### 1.3 座標系統

| 代號                | 全名                                                             | 出現於                                    |
| ------------------- | ---------------------------------------------------------------- | ----------------------------------------- |
| **WGS84**     | 經緯度（`longitude`/`latitude`/`Px`/`Py`）               | 重要地標以外的有座標資料                  |
| **TWD97 TM2** | 二度分帶橫麥卡托，中央經線 121°E、`k0=0.9999`、東偏 250,000 m | 重要地標`twd97_x/y`、停車場 `TW97X/Y` |

**已實測交叉驗證**（§8.3）：
`重要地標` 的「樹林站前站」TWD97 `(292878, 2764872)` 轉 WGS84 為 `(121.424754, 24.991218)`，
距 `公車站位` 資料中的「樹林火車站」站牌 **23 公尺** —— 兩個獨立來源的座標系統換算正確、資料彼此吻合。

> TWD97 TM2 是**平面投影座標，單位為公尺**，同系統兩點可直接用 `hypot(Δx, Δy)` 求直線距離，
> 在台灣範圍內誤差 < 0.1 %。WGS84 與 TWD97 混用時必須先換算，不可直接比較。

## 6. 缺口與風險

### 6.1 ★最大缺口：沒有地價區段界線

表3 的每一個距離都是「**本區段中心點**至該設施」（[dev/03 §S2](03-設施類區域因素填表規範.md)），
而且「本區段內／外」核取方塊在某些基準表中**自成一級**（金山區站牌欄，勾內與距 150 m 差一整級，
見 [dev/03 §3.4(a)](03-設施類區域因素填表規範.md)）。

**這兩件事都需要區段幾何，而 18 個來源都沒有。** 本案 `datasets/regions/shulin/segments/*.json` 的
區段資訊也只有文字範圍描述（`scope_desc`，例如「沿八德街以西、啟智街及未開闢計畫道路以南⋯⋯」），無座標。

> **［2026-09-13 現況］** 仍然成立的是「18 個來源都沒有區段幾何」。已解決的是「因此算不出距離」：
> 界街名稱本身就是幾何線索，OSM 的街道線段補上了這 18 個來源缺的那一塊。
> 中心點與不確定半徑見 `datasets/external/poi_inference.json` 的 `segments`。

已查證的替代圖資（**皆不是地價區段界線**）：

| 圖資                               | 來源                                                                                                            | 可替代性                                    |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 新北市都市計畫土地使用分區及範圍圖 | [data.ntpc.gov.tw/datasets/fe26e0a5-...](https://data.ntpc.gov.tw/datasets/fe26e0a5-54c2-4876-bbc7-150243c048f5) | ❌ 使用分區 ≠ 地價區段                     |
| 新北市里界圖資                     | [data.ntpc.gov.tw/datasets/8bbd1aca-...](https://data.ntpc.gov.tw/datasets/8bbd1aca-752c-4df0-b515-1cfd88b36274) | ❌ 里界遠大於地價區段                       |
| 新北市土地段代碼對照表             | [data.ntpc.gov.tw/datasets/beb682b5-...](https://data.ntpc.gov.tw/datasets/beb682b5-e074-440f-aabf-7d9375fb59de) | ⚠️ 僅段名↔段代碼對照（1,869 筆），無幾何 |

**因應方式（依優先順序）：**

1. **向地政局索取地價區段圖 SHP**（`地價區段界線` 圖層）—— 唯一根本解；
2. **由 `scope_desc` 的道路邊界文字反推多邊形** —— 可行但工程量大、且有歧義（「未開闢計畫道路」無實體）；
3. **以區段內已知地標取代中心點** —— 誤差數百公尺，對最內門檻 200～300 m 的細項不可接受；
4. **退回「核對模式」** —— 不自行計算距離，僅檢查表3 已填數值是否與本批資料的設施清單**矛盾**
   （例如表3 填「無焚化爐」但樹林焚化廠在冊 → 提示複核）。

> **建議本階段採 4。** 這仍有實質價值：能抓出「該填而未填」「填無但實際有」兩類最常見的退補事由，
> 且完全不依賴區段幾何。
