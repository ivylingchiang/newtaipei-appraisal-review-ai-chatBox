## 1. 這份檔案回答什麼

前四個 version 回答「**算出來是多少**」，這一份回答「**每一格應該從哪裡來**」：

| 問題 | 在哪一個頁籤 |
|---|---|
| 表3 這一欄的優劣等級，依據是哪一條級距？填在表5 哪一列？ | 表3 地價區段勘查表 |
| 表4 這一格的條件欄應該抄自哪張表？差異率查表方向為何？ | 表4 比較法調查估價表 |
| 表5 這一格的修正百分比怎麼算出來的？小計、總修正數怎麼加？ | 表5 影響地價區域因素分析明細表 |
| 目前哪些資料缺、缺了會影響哪幾格、最大多少百分比？ | 缺少的資料與替代方式 |
| 留白處目前用哪個 API／哪種計算方式頂替？可信度多少？ | 開放資料來源 |
| 手冊的公式、尾數規則、R1–R14 交叉檢核、官方審查檢核表 | 公式與審查規則 |

前三個頁籤中，**每一個欄位與每一個儲存格都可以點**。點下去右側顯示：

- **應對照的表格與欄位** —— 基準明細表細項 → 表3 儲存格 → 表5 列位／表4 列位 →
  同名之個別因素（避免重複修正）→ 上游的表1-1／表7
- **計算公式** —— 判級、修正率查表方向、小計、總修正數、價格鏈，逐段列出
- **級距門檻** —— 評價基準明細表原文，以及完整的 N×N 反對稱修正矩陣
- **目前資料狀態** —— 四個區段各自的等級、依據、信心等級、是否臨界
- **替代使用之資料來源** —— 該欄位目前用哪些開放資料頂替，附連結與信心等級
- **本案專屬規則** —— CR1（捷運開發區）、CR2（8m 以下道路容積率）
- **手冊依據** —— 該欄位適用的手冊條次原文

## 2. 狀態分類

| 色 | 狀態 | 意義 |
|---|---|---|
| 綠 | 可查表 | 題目原載事實 × 評價基準明細表，無估算成分 |
| 藍 | 外部推算 A/B | 主管機關名冊（A 自帶座標／B 座標由第三方補齊且可交叉比對） |
| 紫 | 外部推算 OSM | 僅 OpenStreetMap，群眾協作，無機關背書 |
| 金 | 代理判準 | 級距或設施定義由本專案代設（19 接近商圈、21 停車方便性） |
| 橙 | 區段推定 | 表3 之區段層級記載推定至宗地層級，不具宗地個別性 |
| 橙 | 覆蓋不足 | 嫌惡設施子欄缺漏 → 推算等級僅為樂觀上限，不得判級 |
| 紅 | 留白退補 | 應填而無任何可用資料 |
| 灰 | 敘述型／不適用 | 基準表列為敘述型無矩陣；或普通住宅用地無此細項 |

「查不到」永遠不等於「無」：正向設施填「無」＝最劣級，嫌惡設施填「無」＝最優級，
兩者都直接改變修正率，故不確定的格子一律留白。

## 5. 關於重複修正

表5（區域因素）與表4（個別因素）有 14 組同名細項（使用分區、建蔽率、容積率、禁限建、
地勢、道路、接近學校／市場／公園／車站、停車、嫌惡設施）。

手冊 伍、六(九)：**已於一方完全反應者，不得於另一方重複調整。**
題目表5 備註欄亦載明「使用分區、建蔽率、容積率修正併同於比較法調查估價表宗地個別因素
考量調整修正」—— 兩者擇一由承辦單位認定。頁面於每一個同名細項的詳細面板中標示此關係。
